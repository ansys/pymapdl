# AGENTS.md

Instructions for AI coding agents working in the PyMAPDL repository.
This is the single source of truth; `CLAUDE.md` just points here.

PyMAPDL (`ansys-mapdl-core`) is the Python client library for Ansys MAPDL.

## Repository layout

| Path | Content |
|---|---|
| `src/ansys/mapdl/core/` | Library source |
| `src/ansys/mapdl/core/_commands/` | **Auto-generated. Never edit.** |
| `src/ansys/mapdl/core/mapdl_extended.py` | `_MapdlCommandExtended`: where MAPDL command behavior is overridden |
| `src/ansys/mapdl/core/launcher/` | Launching and connecting to MAPDL |
| `tests/` | Test suite; shared fixtures and helpers in `tests/conftest.py` |
| `doc/source/` | Sphinx documentation |
| `doc/changelog.d/` | Towncrier changelog fragments (generated by CI/CD; do not add) |
| `examples/` | Gallery examples |
| `.github/agents/` | Specialized agent definitions |

## Environment

Use `uv` for everything. Fall back to the repository `.venv` only if `uv` fails.

```sh
uv sync --all-extras          # install dependencies
uv run pytest                 # run tests
uv run pre-commit install     # install hooks (once)
uv run pre-commit run --all-files
```

Supported Python: 3.10 - 3.14.

## Hard constraints

- Never modify anything under `src/ansys/mapdl/core/_commands/`. To change the
  behavior of a MAPDL command, override it in `_MapdlCommandExtended` in
  `src/ansys/mapdl/core/mapdl_extended.py`.
- Never break backward compatibility. Deprecate instead, with a warning and a
  removal version.
- Never add files to `doc/changelog.d/`. Changelog fragments are generated
  automatically by CI/CD when the pull request is opened.
- Never commit secrets, credentials, or license server details.
- Pre-commit must pass before every commit. It is mandatory and runs `black`,
  `isort`, `flake8`, `mypy`, `codespell`, `numpydoc-validation`, `bandit`,
  license headers, and more.

## Code style

- PEP 8, enforced by `black` and `isort` (`profile = "black"`).
- Type hints on new public APIs. `mypy` runs on `src/` through pre-commit.
- No bare `except:` and no overly broad exception handling. Catch the specific
  exception, or the narrowest useful base class.
- Group nested context managers:

  ```python
  with (
      context_manager_0 as cm0,
      context_manager_1 as cm1,
  ):
      do_something()
  ```

- Comment only what needs clarification. Docstrings carry the explanation.

## Docstrings

All public functions, methods, and classes need **numpydoc** docstrings with at
least a summary, `Parameters`, `Returns`, and `Examples`. Active checks live in
`[tool.numpydoc_validation]` in `pyproject.toml` and are enforced by pre-commit.

## Connection modes

PyMAPDL reaches MAPDL through two connectivity modes and two connection types:

- Connectivity: `local` (MAPDL on the same machine) or `remote`.
- Connection type: `grpc` (default, recommended) or `console` (`pexpect`-based,
  Linux only, discouraged and effectively legacy).

Code must not assume `local`; guard filesystem access that only works locally.

## Testing

Target **≥90% coverage** for new or changed code.

```sh
uv run pytest tests/test_foo.py::test_bar          # targeted
uv run pytest --cov=ansys.mapdl.core --cov-report=term
```

Notes:

- `--maxfail=2` and `--random-order` are set in `pyproject.toml`. Override
  locally with `uv run pytest -p no:randomly --maxfail=100`.
- Coverage is on by default through `addopts`.

### MAPDL instances are expensive: mock by default

Most agent work should not launch MAPDL. Use `unittest.mock`:

```python
from unittest.mock import Mock, patch


def test_feature_without_mapdl():
    mock_mapdl = Mock()
    mock_mapdl.get_value.return_value = 42
    ...
```

To run only the tests that do not launch MAPDL:

```sh
export PYMAPDL_START_INSTANCE=False   # Windows: SET PYMAPDL_START_INSTANCE=False
uv run pytest
```

### Conditional skipping

Use `requires()` from `tests/conftest.py`, not `pytest.mark.skipif`:

```python
from conftest import requires


@requires("local")
def test_local_feature(mapdl): ...


@requires("grpc")
def test_grpc_feature(mapdl): ...
```

Accepted values: `local`, `remote`, `grpc`, `dpf`, `console`, `gui`, `linux`,
`nolinux`, `windows`, `nowindows`, `xserver`, `cicd`, `nocicd`, or any
importable package name.

### Environment variables

| Variable | Purpose |
|---|---|
| `PYMAPDL_START_INSTANCE` | `False` connects to an existing instance instead of launching one |
| `PYMAPDL_PORT` | gRPC server port (default `50052`) |
| `PYMAPDL_IP` | gRPC server IP (default `127.0.0.1`) |
| `ON_LOCAL` | Force `local` mode detection |
| `ON_CI` | Mark the run as CI; some tests skip |

### CI-like runs with tox and Docker

Copy the `example.env` next to each Docker directory to `.env`; tox loads it.

```sh
uvx tox -e docker-run-mapdl       # start MAPDL container (add -dpf for DPF too)
uvx tox -e docker-test-local      # run tests against local images
uvx tox -e docker-test-remote     # mirror CI exactly
uvx tox -e docker-stop-mapdl
```

Other useful envs: `style`, `doc`, `docker-test-local-build`,
`docker-test-remote-build`.

## Documentation

- Prose follows the Google developer style guide; docstrings follow numpydoc.
- Use `Ansys`, not `ANSYS` (except in copyright headers).
- U.S. spelling. Prefer unhyphenated forms such as `postprocessing`.
- Sentence case for headings; simple verb forms ("Run tests", not "Running tests").
- Active voice. Put the *why* before the link.
- Avoid `e.g.`, `i.e.`, `etc.` and location words such as "above" and "below".
- Always name the entity type: "the `run()` method", "the `Mapdl` class".
- Use the full dotted path in Sphinx roles:

  ```rst
  :meth:`mapdl.run() <ansys.mapdl.core.Mapdl.run>`
  ```

- Add new technical terms to `doc/styles/config/vocabularies/ANSYS/accept.txt`
  so `codespell` and `vale` pass.
- New gallery examples go under `examples/` in `00-mapdl-examples/`,
  `01-geometry/`, `02-tips-n-tricks/`, or `03-general-fea/`.

```sh
cd doc && make html
uv run codespell doc/ src/
```

## Dependencies

- Runtime dependencies: `[project].dependencies` in `pyproject.toml`, with
  range specifiers.
- `tests` and `doc` extras: exact pins (`==`).
- Run `uv lock` after any change and do not commit unrelated lock churn.

## Changelog

**Do not create changelog fragments.** The CI/CD pipeline generates the
towncrier fragment in `doc/changelog.d/` automatically when the pull request is
opened, deriving the name and type from the pull request number and prefix.
Writing one by hand causes duplicates and conflicts.

## Branches, commits, and pull requests

Branches use `prefix/`, commits and pull request titles use `prefix:`. Allowed
prefixes: `build`, `ci`, `docs`, `feat`, `fix`, `maint`, `perf`, `refactor`,
`release`, `revert`, `testing` (plus `chore:` for commits and `junk/` for
throwaway branches).

## Specialized agents

Definitions live in `.github/agents/`:

- `developer.agent.md` - features, bug fixes, performance, API design
- `tester.agent.md` - coverage, mocking, test infrastructure
- `documentation.agent.md` - docstrings, style, vale and codespell
- `reviewer.agent.md` - review checklist and merge gate

Workflow: **developer → tester → documentation → reviewer → merge**.
